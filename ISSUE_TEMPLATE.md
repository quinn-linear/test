# Issue Template and Guidelines

## Overview

This document provides guidelines and a template for creating clear, actionable issues in our project tracking system. Well-structured issues help the team understand requirements, scope, and acceptance criteria.

> **Note**: GitHub automatically offers issue templates from the `.github/ISSUE_TEMPLATE/` directory when creating new issues. The following templates are available:
>
> * [Standard Issue Template](./.github/ISSUE_TEMPLATE/issue_template.md) - For general tasks and issues
> * [Bug Report Template](./.github/ISSUE_TEMPLATE/bug_report.md) - For reporting bugs
> * [Feature Request Template](./.github/ISSUE_TEMPLATE/feature_request.md) - For suggesting new features

## Issue Title Guidelines

A good issue title should:
- Be specific and action-oriented
- Clearly indicate what needs to be done
- Be concise (typically 5-10 words)
- Start with a verb when describing a task (e.g., "Implement", "Fix", "Optimize")

Examples:
- ✅ "Implement user authentication flow"
- ✅ "Fix registration form validation errors"
- ✅ "Optimize database queries for product listing page"
- ❌ "rewwe" (vague, not descriptive)
- ❌ "bug" (too general)

## Issue Description Template

Our standard issue template (available when creating a new issue in GitHub) follows this structure:

```markdown
### Overview
[Brief description of the issue or feature - what needs to be done and why]

### Background / Context
[Relevant information about why this issue exists, any history or predecessor issues]

### Objectives / Success Criteria
[List of specific objectives that will indicate success]

### Scope & Approach
[Define what is in and out of scope, and suggest an implementation approach if relevant]

### Acceptance Criteria
[Specific, testable criteria that must be met for this issue to be considered complete]

### Dependencies & Risks
[List any dependencies on other issues/systems or potential risks]
```

## Best Practices

1. **Be Specific**: Vague descriptions lead to misunderstandings and scope creep
2. **Include Context**: Help others understand why the issue is important
3. **Define Boundaries**: Clarify what is in-scope and out-of-scope
4. **Link Related Issues**: Reference related or dependent issues
5. **Use Screenshots/Examples**: Where applicable, include visual references
6. **Update Regularly**: Keep the issue updated with new information

## Process for Unclear Issues

If you encounter an issue with an unclear title or insufficient description:
1. Tag relevant stakeholders for clarification
2. Use the template above to request specific information
3. Consider scheduling a quick meeting for complex clarifications

Remember: Well-documented issues save time and reduce misunderstandings throughout the development process.
